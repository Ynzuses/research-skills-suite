## Pre-stable history

# Changelog

## 0.9.0 - Unreleased

- Added task-aware capability checkpoints at phase, target/format/system changes, compaction/resume, and material tool failures, with equal consideration of relevant user-maintained, third-party, system, and plugin Skills.
- Added progressive Skill/tool/MCP discovery and method/executor composition guidance, distinguishing current exposure, instruction/schema reads, target access, and observed execution; project routes remain a shortlist rather than an allowlist.
- Extended discoverable entry, blueprint, memory, and status templates with refresh triggers and concise capability continuation for unfinished work, without copying machine catalogs or expanding permissions.
- Added routing scenarios for phase changes, stale handoffs, third-party capabilities, unavailable connectors, and tasks that need no specialist. No runtime watcher or model-context reliability guarantee is introduced.

## 0.8.0 - 2026-10-20 (local iteration; unpublished)

- Added event-driven directory reassessment before output batches, after revision/phase closure, and at materially changed handoff, including crowded child, archive, source, and scratch directories.
- Added lifecycle classification and proportionate reorganization guidance: preserve current artifact families, required dependencies, frozen identities, successor routes, and move integrity; reuse existing authorization and avoid age/count-based deletion.
- Connected directory maintenance to the Skill entry, session workflow, architecture, audit guidance, and discoverable workspace templates.
- Added a dependency-free read-only directory metadata inspector with configurable review signals, explicit exclusions, repository/link boundaries, incomplete-read reporting, and synthetic regression coverage. Counts do not establish redundancy or authorize moves.

## 0.7.0 - 2026-10-08 (local iteration; unpublished)

- Extended `manage-workspace-memory` startup and closure with optional, read-only Git orientation. It records repository roots, branch or detached state, `HEAD`, work-tree status, recent local history, and nested repository boundaries without making Git a prerequisite or performing network or commit operations.
- Added SemVer 2.0.0 version records that distinguish receiver-facing correction rounds from owner-led workflow iterations, keep review revisions separate from release compatibility, and bind submitted identities to content hashes and Git coordinates.
- Added dependency-free Git and workspace-version helpers with regression tests, plus public documentation recommending Git for faster recovery and provenance.

## 0.6.0 - 2026-08-20

- Hardened the four flagship workflows around machine-verifiable release contracts: transactional workspace bootstrap, strict evidence-bundle closure, adversarial DOCX/OpenXML inspection, and confirmatory genotype-imputation benchmark freezing.
- Upgraded workspace bootstrap from a proposed layout helper to a root- and manifest-bound, approval-gated operation with dry-run plan identity, link/reparse/hard-link defenses, atomic replacement, rollback evidence, and idempotent re-application tests.
- Added literature screening supersession semantics and a strict-release mode that admits only the unique current inclusion decision and requires delivered full-text hashes to match the source manifest.
- Expanded document package auditing for OPC relationship escape, external local-file targets, comments/people/revision closure, and the rule that unavailable required rendering permits only a limited candidate handoff.
- Added genomics study-contract modes for variant discovery, existing genotypes, association-only analysis, and reference audit, with explicit not-applicable boundaries and hypothesis-to-evidence-to-output-to-validation closure.
- Replaced the imputation benchmark contract with schema 2.0: versioned truth-free input registries, workflow input closure, design-bound pilots, structured downstream endpoints, complete leakage declarations, non-boolean condition dimensions, and a frozen confirmatory fingerprint.
- Strengthened computational strict-complete validation so failed or undeclared tasks, orphan completion-critical outputs, zero attempts, empty success markers, and invalid produced-record counts cannot pass; ordinary validation now reports a structural rather than completion verdict.
- Added deterministic public-layout export, repository governance files, public/direct installation documentation, dual-layout checks, release manifests, and candidate-wide `SHA256SUMS` generation while retaining a clean-history boundary from private workspaces.
- Bound activation scoring to an exact exported candidate, an exact clean installed tree, an external evidence manifest, unique fresh-session identities, transcript hashes, and an independent reviewer identity; a detached hand-written result table is no longer release-eligible.
- Added an external-trust release policy and candidate-outside verification flow so package self-tests and candidate-owned validators cannot alone issue a release verdict; release thresholds, verifier identities, evidence identities, and post-execution tree integrity are fixed by the review policy.
- Raised the golden prompt suite to 67 target-aware cases and added adversarial regression coverage for Windows UTF-8/CP936 operation, path and link attacks, stale fingerprints, leakage omissions, downstream endpoint omissions, and release self-certification attempts.

## 0.5.0 - 2026-08-20

- Repositioned the eight-Skill suite as four flagship products, three strong specialists, and one deliberately narrow cross-stage orchestrator; retained every Skill after an independent value and overlap audit.
- Made implicit invocation explicit in every `agents/openai.yaml` and tightened trigger descriptions, incomplete requests, near-neighbor exclusions, and single-stage delegation boundaries.
- Upgraded `manage-workspace-memory` with project-characteristic profile inference, deliverable/authority-first directory blueprints, an active `AGENTS.md` routing template, event-queued minimal maintenance, no-event/no-write behavior, and explicit limits on background monitoring and write authority.
- Added a dependency-free, read-only workspace-memory auditor with strict UTF-8 handling, stable text/JSON output, link/path/placeholder/ID/status/frozen-baseline checks, and synthetic Chinese-path tests.
- Added machine-readable contracts and validators for evidence bundles, scientific revision state, document delivery, multi-stage workflow state, computational runs, complex-genome studies, and genotype-imputation benchmarks.
- Added a read-only DOCX/OpenXML package auditor covering ZIP safety, relationship targets, comment/people/presence closure, tracked changes, fields, equations, notes, and external relationships without claiming visual validation.
- Rebuilt `rigorous-research-workflow` as a lifecycle state machine and invalidation router instead of duplicating specialist writing and document-engineering instructions.
- Added resume-before-restart contracts for workspaces, literature reviews, revision rounds, and document deliveries, plus exact handoff fields between evidence, content, delivery, and persistent workspace state.
- Replaced the structural-only trigger list with a target-aware golden specification covering direct, indirect, incomplete, boundary, composition, and negative cases for all eight Skills.
- Added an activation-result scoring harness for clean-install forward tests, with recorded model/date, exact loaded Skills, behavioral grading, per-Skill precision/recall, and explicit thresholds.
- Expanded dependency-free regression tests for validators, Windows UTF-8 behavior, path safety, zero-versus-missing state, hash binding, contract cross-references, and activation scoring.

## 0.4.0 - 2026-08-03

- Added a citation-delta audit for pruned or expanded reviews, covering orphan references, unsupported additions, evidence-role mismatches, citation inflation, full-text identity, and short-summary consequences.
- Added an epistemic-status ledger that distinguishes source-reported facts, review synthesis, conditional inference, approved project decisions, and open options across body text, tables, conclusions, abstracts, and external summaries.
- Added short-summary parity checks so discussion material cannot silently become a fixed implementation route when compressed for handoff.
- Added a submitted-baseline freeze: formally circulated documents are immutable by exact identity, and later comments start a new revision with fresh authority, synchronization, and validation records.
- Strengthened public productization so reusable releases retain generalized failure patterns, repair rules, and acceptance tests while excluding local incidents, reviewer wording, hashes, source identities, and unpublished conclusions.
- Added four golden prompts and forward-test gates for citation deltas, epistemic-status repair, submitted-baseline revision, and privacy-safe experience generalization.

## 0.3.8 - 2026-07-30

- Added a closure rebind gate: final status, README, asset-index, and audit-pointer edits must be followed by a fresh physical-artifact hash check, rather than relying on a pre-metadata audit.
- Added an explicit limitation rule for unavailable authoritative rendering so stale page counts are never inherited.
- Added Windows UTF-8 guidance for the official Skill validator and a post-deployment recheck after metadata edits.

## 0.3.7 - 2026-07-30

- Required supporting methods to be introduced by positive scientific function before any scope boundary or future-work handoff, preventing openings that still read as replies to reviewer comments.
- Required explicit attribution of literature-derived syntheses and conditional wording for not-yet-observed diagnostic patterns, including table titles, headers, rows, recommendations, and conclusions.
- Added cross-surface consistency checks so external comparators cannot be cautiously bounded in prose but silently upgraded to causal tests in tables.
- Strengthened DOCX formula validation to check variable text, math font, italic state, and vertical alignment by semantic role instead of relying on aggregate superscript counts.

## 0.3.6 - 2026-07-30

- Added a scope-statement budget and meta-discourse deletion pass so a correct document boundary is not mechanically repeated through methods, tables, validation, limitations, and conclusions.
- Required structural prominence checks independent of disclaimers, covering heading level, paragraph share, table space, recommendations, and conclusion emphasis.
- Strengthened clean DOCX validation to remove people/author and presence parts plus their relationships and content types, and to preserve token-specific run formatting when paragraphs are rebuilt.

## 0.3.5 - 2026-07-30

- Added a three-level prominence contract separating overall project requirements, the current document's responsibility, and supporting assets or deferred deliverables.
- Prevented both scope errors: silently dropping a project-level required method and overcorrecting by making that method the center of a narrower review that only needs to preserve it as a bounded lead.
- Extended whole-document audits and golden prompts so heading depth, paragraph space, tables, recommendations, and conclusions reflect the same scope hierarchy.

## 0.3.4 - 2026-07-29

- Added a term-necessity and placement gate before first-use explanation: decide whether a specialist label should be omitted, relocated, or defined, and explain it only at its first functional use rather than inserting a definition at the review anchor.
- Added a paragraph-role gate for comment-driven revision and a cross-location concept audit spanning the opening, substantive section, tables, recommendations, and conclusion; local explanatory patches must advance the surrounding argument.
- Protected explicitly required method families or training components from being silently demoted while repairing classification errors, while still locating each trainable component on a concrete internal computation.
- Strengthened Word review adjudication so a comment location is treated as diagnostic evidence rather than the default insertion point, and added two golden prompts covering forced definitions and required machine-learning training.

## 0.3.3 - 2026-07-29

- Added an enforceable mechanism-first explanation gate: establish the input, intermediate objects, operations, and output before listing technical modules, then explain first-use terms as plain-language meaning, standard term, and concrete role.
- Added a concrete-predicate audit requiring consequential “change,” “form,” “enter,” and “provide” statements to identify the affected object, operation, and observable result.
- Clarified that reviewer example rewrites and direct tracked edits are proposed wording unless explicitly designated final; preserve authoritative corrections while independently producing the strongest reader-facing prose.
- Strengthened removal of reviewer dialogue and writing-process meta-discourse, added imputation-specific mechanism-chain guidance, and added two golden prompts covering these failure modes.

## 0.3.2 - 2026-07-29

- Added a purpose contract for long and multi-round research writing: objective, intended contribution, object being changed or explained, and excluded substitutes must remain aligned across sections, tables, recommendations, conclusions, and short summaries.
- Added document-wide recovery when feedback exposes purpose drift; auxiliary workflows, proxies, or post-processing steps must not silently replace the requested research contribution.
- Strengthened Word-Markdown synchronization for structural moves across tables: align captions by identity, move existing nodes with their formatting, preserve automatic fields, and compare the final reading order including table cells.
- Added an explicit optimization-object gate for imputation benchmarking and source-level innovation, including matched original-versus-modified comparisons and module ablations.

## 0.3.1 - 2026-07-28

- Added a method-to-judgment bridge from method characteristics to consequences for comparability, validation, and research role.
- Strengthened comment generalization so annotated defects are checked across unannotated later sections without leaving answer-to-reviewer scaffolding in reader-facing prose.
- Added final handoff-directory hygiene, hash-bound audit reuse, task-owned Office-process cleanup, and numbered full-text readability checks.
- Added three golden prompts for heading generalization, pruned evidence packages, and clean Word-plus-full-text delivery folders.
