# Support

Use the repository's GitHub Issues for installation questions, reproducible bugs, trigger false positives or false negatives, documentation gaps, and feature proposals. Include the suite version, Codex surface and build when known, operating system, installation method, a privacy-safe prompt or fixture, expected behavior, and observed behavior.

Do not attach private research data, unpublished documents, credentials, personal paths, or proprietary full texts. Reduce the report to a synthetic reproducer whenever possible.

Security-sensitive reports should follow [SECURITY.md](SECURITY.md) instead of using a public issue.
